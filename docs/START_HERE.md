# Your first 30 minutes

Open this file whenever you return to the project. The aim today is to see a working data-to-answer flow, explain it in plain language, and save where you stopped.

## 1. Get the project

Clone [your learning repository](https://github.com/thisislife433-dotcom/ai-fde-learning) with **Git > Clone repository** in VS Code, or run:

```bash
git clone --recurse-submodules https://github.com/thisislife433-dotcom/ai-fde-learning.git
cd ai-fde-learning
```

If you downloaded the companion ZIP, extract it and open the `ai-fde-learning` folder in VS Code. The offline exercises work immediately. When you want the original project, run `python scripts/fetch_upstream.py` with Git installed; this downloads the pinned public source. GitHub ZIPs and the companion archive do not contain Git submodule contents.

## 2. Check Python

- Windows PowerShell: `py -3 --version`. Use `py -3` in place of `python` below if required.
- macOS/Linux: `python3 --version`. Use `python3` if `python` is not available.
- Python **3.10+** runs the offline lab. Use a separate **3.12** environment for the original project.

You do not need Docker, an API key, Pinecone, an Azure subscription or an AWS account for today's lab.

## 3. Run the example

From the repository's top-level folder:

```bash
python scripts/doctor.py
python -m lab demo
```

Read these parts of the output:

| Field/result | Meaning |
|---|---|
| `mode: offline deterministic lab` | This response is generated by fixed Python logic, not an LLM |
| `data_source: synthetic fixture` | These are made-up teaching records |
| `as_of` | We use the fixture's fixed clock so exercises stay reproducible |
| `MEL-101: TEMPERATURE_BREACH` | 6.2 C exceeds the fictional lab limit; its delay also needs review |
| `MEL-102: WITHIN_LAB_LIMITS` | Its recent 3.0 C reading is within this exercise's range |
| `MEL-103: UNKNOWN_CURRENT_STATUS` | Its reading is old, so the current condition is unknown |
| `citations` | Rule IDs that support the recommendation |
| `weather: not connected` | The lab does not invent weather |
| `actions_executed: false` | Nobody has been contacted and no shipment has been rerouted |

The lab writes its SQLite database and an append-only-in-this-program JSONL trace under ignored `runtime/`. The OS user can edit these files; they are not immutable audit storage.

## 4. Ask three different questions

```bash
python -m lab ask "Which shipments in Melbourne need review?"
python -m lab ask "What are the temperature rules?"
python -m lab ask "Delete all shipments"
```

The second question uses policy lookup without querying the database. The third is refused. The question router understands only a few teaching intents. It is not a general chatbot, a prompt-injection defence, or a substitute for the upstream AI implementation.

Then inspect the facts and rules separately:

```bash
python -m lab sql
python -m lab policy
```

## 5. Verify and explain

```bash
python -m unittest discover -s tests -v
```

Explain aloud: **What came from the data, what came from policy, and what was inferred?** Why is an old high-temperature reading different from proof that cargo is hot now?

Run `python scripts/review.py --limit 5` for five recall cards. Your answers are not recorded; only self-rated due dates are stored locally under `progress/private/`. Back that folder up yourself if you want those personal due dates preserved across devices.
